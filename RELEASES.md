# Vibemis build timeline

The chronological, newest-first build timeline — every alpha, beta, RC and stable in the
order it actually shipped, which GitHub's Releases page cannot show (it sorts by SemVer
precedence, so alphas always sink below betas of the same version).

### → **[Open the live build timeline](https://github.com/navyas321/vibemis/blob/releases-index/RELEASES.md)**

It is regenerated by `scripts/gen-releases-index.sh` on every release cut and published to
the [`releases-index`](https://github.com/navyas321/vibemis/tree/releases-index) branch.

<details><summary>Why it lives on a branch instead of in this file</summary>

`vibemis-main` is protected and the release job runs as `github-actions[bot]`, which is
not an admin, so it cannot push here directly. The obvious workaround — have the bot open
a pull request — turned out to be impossible rather than merely awkward: GitHub suppresses
the `pull_request` event for a `GITHUB_TOKEN`-authored PR, so required status checks are
never attributed to it. On PR #290 all three required contexts finished **green on the
PR's exact head commit** and the PR's status rollup was still **empty**, leaving branch
protection permanently unsatisfied. A plain merge answered *"base branch policy prohibits
the merge"*; `--auto` never fired at all. Six consecutive release cuts each opened a bot
PR that could not merge and was closed minutes later, while this file sat six releases out
of date.

Pushing to an ordinary unprotected branch has none of those problems, needs no PAT and no
admin bypass, and matches no workflow trigger, so it starts nothing. This page is a
pointer rather than a copy so the timeline stays discoverable from the repo root without
ever going stale again.
</details>
